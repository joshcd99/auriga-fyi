GreenStep

Sustainability challenge app · CS / technical · Failure story

GreenStep is a sustainability-challenge app: you pick small environmental habits (no single-use plastic, bike-instead-of-drive, etc.), log streaks, and compete with friends. It's deployed at greenstep.auriga.fyi.

Keywords: sustainability, behavior change, gamification, web app, full-stack, failure, lessons learned, user research, scoping.

1. What I was trying to do (context)

{ TODO — Example: I wanted to build a sustainability app that would actually change behavior, not just guilt people. The pitch was: gamify small green habits, make tracking frictionless, lean on streaks and friend-pressure to drive consistency. I imagined classmates using it daily during the semester. }

2. What didn't go as well as I hoped

{ TODO — the honest failure. Example: I shipped the app and almost nobody used it past the first week. Even I stopped logging after a few days. The features I'd assumed were the value (streak math, leaderboards, badges) were not the value — they were noise on top of a fundamental problem: the friction of logging anything daily is enormous, and competing on virtue feels bad, not motivating. I'd built the thing I imagined instead of researching the thing people actually wanted. }

3. What I learned and what I do differently now

{ TODO — the change. Example: I learned that "would I use this?" is not the same as "will real users adopt this?" — and that even I am a worse predictor of my own behavior than I thought. Now I start projects by talking to 3–5 prospective users before writing code, sketch the smallest possible thing that could deliver value, and only add features after I've watched someone actually use the prior version. The Distribution tooling work was the first time I applied this discipline rigorously — and the adoption difference was night and day. }
